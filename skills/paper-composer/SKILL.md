# Paper Composer

把“机构模板”和“用户大纲”当作两类不同权威的输入：**模板决定格式，用户大纲决定论证，证据决定事实**。任何冲突都显式列出并由用户裁决，不静默改写。

## 输入

1. **机构模板**（格式权威）
   - LaTeX：`.tex` 示例稿、`.cls` / `.sty`、含示例稿的 `.zip`。
   - Word：`.docx` / `.dotx`。
   - 仅有 PDF 或网页投稿指南时，先提取文字再剖析；无法提取时请用户提供可读文本或可访问内容。链接本身不是模板证据。
2. **用户内容大纲**（内容权威）
   - Markdown、Word、PDF 或聊天中的结构化提纲。
   - 至少包含：中心论点、章节意图、关键结果、已有图表与数据、必须说与不能说的内容。
3. **证据库**
   - 实验数据、日志、指标、图表、表格、参考文献、既往稿件、补充材料。
4. **投稿元数据**
   - 目标单位或期刊、栏目、语言、匿名要求、页数或字数限制、作者与单位、基金、利益冲突、数据可用性声明、截止时间。

## 工作区

优先使用用户指定目录；否则使用当前工作目录。建议结构：

```text
manuscript/
├── manuscript.yaml
├── inputs/
│   ├── institution_template/
│   ├── outline/
│   └── evidence/
├── template/
│   ├── profile.json
│   └── report.md
├── evidence/manifest.json
├── outline/outline_map.md
├── sections/
├── bibliography/
├── build/
├── outputs/
└── reports/compliance.md
```

初始化命令（先预览）：

```bash
python <skill-dir>/scripts/init_manuscript.py --root <manuscript-root> \
  --title "<论文题目>" --format latex --language zh --dry-run
```

确认后移除 `--dry-run`。脚本只补齐缺失文件，不覆盖已有内容。依赖 Python 3.9+；校验脚本需要 PyYAML（见仓库 `requirements.txt`）。

## 核心工作流

### 0. 输入门

确认四类输入是否齐备：机构模板、用户大纲、证据库、投稿元数据。缺模板或大纲时先补齐，不凭经验直接开写。把未知字段记为 `unknown`，只追问会阻塞当前阶段的字段。

### 1. 模板剖析

运行：

```bash
python <skill-dir>/scripts/inspect_template.py \
  --root <manuscript-root> --path <机构模板文件或目录>
```

生成 `template/profile.json` 与 `template/report.md`，提取：

- 文档类、页面尺寸、页边距、分栏、行距、字号与字体。
- 章节层级、编号规则、摘要、关键词、附录与致谢位置。
- 引用样式、参考文献格式、图表标题格式与编号方式。
- 必需声明、匿名要求、页数或字数限制、模板占位符。
- 原生构建方式与可用的示例稿骨架。

自动剖析只读取显式字段。报告中的 `unknown` 项必须回读模板或投稿指南确认，不得猜测为已知。只有 PDF 指南时，结论标记为低置信度。

### 2. 证据盘点

建立 `evidence/manifest.json`，为每项证据分配稳定 ID，登记：

- 类型：`experiment_data`、`metric`、`figure`、`table`、`literature`、`prior_draft`、`external_reference`。
- 路径、来源、生成命令、时间、单位、适用范围和可用状态。
- 可支撑的结论 ID；无法支撑任何结论的资产标记为 `unused`。
- 外部图表必须登记授权与出处；不得伪装成本地实验结果。

数据缺失、指标过期或图表无法复现时列入“证据缺口”，不得用估计值、占位图或虚构引用填充。

### 3. 大纲映射

读取用户大纲，生成 `outline/outline_map.md`：

| 大纲节点 | 模板章节 | 章节目的 | 关键论点 | 证据 ID | 图表 ID | 引用键 | 字数 | 状态 |
|---|---|---|---|---|---|---|---|---|

规则：

- 用户大纲决定论证顺序和重点；模板决定章节命名、层级和长度约束。
- 大纲中的每个关键结果必须绑定至少一个证据 ID；无法绑定的标记为 `gap`。
- 模板要求但大纲缺失的章节（如局限、伦理、数据可用性）列入待补，不得省略。
- 大纲要求但模板不允许的章节，列出冲突并请用户裁决。

### 4. 结构骨架确认

先按模板原生的章节层级生成骨架稿，只包含标题、各节目的、证据占位和引用占位，不写正文。向用户展示骨架、映射表和缺口清单，确认后再进入逐节写作。

### 5. 逐节成稿

按章节分批写作，每批开始前给出本节确认卡：目标、使用的证据 ID、引用、图表、字数预算、仍缺的输入。正文遵守：

- 每个事实性陈述可回溯到证据 ID、引用键或用户确认的内容。
- 数字、单位、实验条件与证据清单一致；不把预期结果写成实测结果。
- 图表在正文中先引用后出现，标题与证据清单一致。
- 引用只来自已登记文献；没有文献支持时改为“本研究观察”或列入缺口。
- 未完成处保留显式占位（如 `[待补：消融实验 E3]`），并在交付报告中列出，不得用编造内容填满。

### 6. 组装与合规

把已确认章节装入机构模板的副本，保留模板的类文件、样式、页眉页脚和继承对象。按模板原生方式构建：

- LaTeX：复制模板到 `build/`，使用模板指定的引擎和参考文献流程（如 `latexmk`、BibTeX/Biber）。
- Word：以 `.dotx` 或示例 `.docx` 为基准生成新文档，保留样式表；不得把模板压平成纯文本。
- Markdown 主稿可作为中间产物，但最终格式必须回到机构模板。

运行合规检查：页数或字数、匿名、作者信息、图表编号、引用完整性、必需声明、文件命名和补充材料。结果写入 `reports/compliance.md`。

### 7. 验收与移交

运行：

```bash
python <skill-dir>/scripts/verify_manuscript.py --root <manuscript-root> --strict
```

校验模板与大纲是否登记、章节是否完整、占位符是否残留、图片与引用是否存在、证据路径是否有效、输出文件是否生成。未通过时按报告修复，不得声称“可投稿”。

向用户汇报：成稿文件、模板剖析报告、证据清单、大纲映射、合规报告、未解决缺口和仍需用户提供的内容。只有用户验收通过后才标记完成。

## 冲突裁决

| 冲突类型 | 裁决 |
|---|---|
| 模板格式与用户大纲排版偏好冲突 | 模板优先；向用户说明差异 |
| 模板必需章节与用户大纲缺失 | 模板优先；生成待补项，请用户提供内容 |
| 用户大纲章节与模板结构不兼容 | 列出两种方案，由用户选择；不得静默删除章节 |
| 大纲论点与证据不一致 | 证据优先；改写论点或标记证据缺口 |
| 引用格式与文献库不一致 | 模板引用样式优先，转换文献格式 |
| 页数或字数限制与内容量冲突 | 先压缩重复表述；仍超限时请用户决定删减范围 |

## 强制规则

- 不修改机构模板原件；所有生成物写入工作区副本，并记录改动位置。
- 不虚构数据、指标、图表、引用、作者信息、基金号或声明。
- 不把搜索摘要、预印本摘要或模型记忆当作已核验文献。
- 不绕过付费墙、登录、验证码或版权限制获取模板与文献。
- 不因“已生成 PDF/DOCX”判定完成；必须通过模板合规、证据追溯和用户验收。
- 不在未确认骨架和章节范围时批量生成全文；一次确认只授权当前批次。
- 模板与大纲冲突时先报告，不擅自替用户做内容取舍。

## 交付物

至少包含：

- `outputs/` 中的成稿源文件与可提交文件（LaTeX 源文件或 DOCX/PDF）。
- `template/profile.json` 与 `template/report.md`。
- `evidence/manifest.json`。
- `outline/outline_map.md`。
- `reports/compliance.md`。
- 缺口清单与用户待确认事项。
